Jev 增强模式 架构图解

五个阶段 + 一个多轮引擎：评委生成 → 确定性分组 → 语义裁决（Jev 核心） → 共识门禁 → Loop 跨轮收敛

Jev 链路（独立 TypeSafe 通道） 主模型通道（评委 / Pi 仲裁器 / Loop） 合并通过 模糊对级联升级（双向） 失败降级安全网 普通数据流
⚡️ 蓝色链路 = Jev 的价值 全部 528~561 个候选对压缩进一次 Noul 批量调用，约 2 秒返回每对的合并概率；走独立 TypeSafe 通道，不占用评委模型的 API 配额与限流额度。
🧠 紫色链路 = 主模型通道 评委生成、Pi 仲裁器（Jev 关闭或模糊对升级时）、Loop 复查都走同一个主模型渠道——共用模型上下文与 Token 配额，这正是 Jev 独立轻量旁路裁决要解耦的开销。
🛡️ 红色虚线 = 安全网 任一裁决调用失败都会以 adjudicationFailed 降级为确定性保守聚合，门禁只紧不松；Jev 合并采用完整链接聚类（组内两两达标才并），链式误并已结构性消除。
